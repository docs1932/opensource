🧱 1. LangChain：
基线框架LangChain作为基础集成层，为语言模型、向量存储、提示符和工具调用结构提供标准接口。
“浅层”代理问题：虽然 LangChain 的基本代理可以在循环中调用工具，但它们是被动响应的。
它们难以处理长时间跨度的任务，因为大型工具的结果会迅速占据提示窗口，并导致状态在不同步骤之间泄露。

🔄 2. LangGraph：
有状态图运行时当代理的循环过于难以预测，无法用简单的链式调用来处理时，就需要使用LangGraph。
LangGraph通过将应用程序建模为状态机来处理多代理编排。
确定性控制：它允许您将严格的、可审计的代码路径与灵活的、模型驱动的步骤混合使用。
生产原语：它通过内置的持久化、流式传输和在每个代理步骤之后进行检查点操作，原生管理上下文保留。

🧠 3. Deep Agents：
自主工具Deep Agents是一个基于LangGraph 和 LangChain构建的框架，它采用预设的框架结构。
用户无需手动连接图节点来构建代理，而是可以使用诸如 `start()` 之类的函数来启动一个开箱即用的、完全配置好的自主工作进程。
它通过四个核心支柱create_deep_agent解决了长时域上下文问题：

🗒️规划工具：将开放式目标分解为结构化的待办事项清单，不断跟踪和调整进度。
📂虚拟文件系统：充当持久的临时文件。数据不再保留在命令提示符窗口中，而是卸载到文件系统中，从而保持 LLM 核心上下文的整洁。
👥子代理委托：生成临时的、隔离的子代理来处理并行工作。任何 LangGraph 图都可以作为子代理传入。
🔒沙盒信任模型：遵循“信任 LLM”的范式，直接在环境级别强制执行安全限制，而不是依靠自我监管。

升级策略指南：你应该选择哪一种？
合理的开发原则是从最适合你工作流程的最高层开始：
如果您需要快速构建原型并集成标准工具调用功能，请从LangChain开始。
如果您需要对图循环、循环逻辑或明确的人工审批步骤进行精确控制，请迁移到LangGraph。
如果您正在构建一个需要并行执行、文件生成和复杂规划的高级代理（例如本地化编码助手或深度研究员），请采用深度代理。
